# Listener

一个用 TypeScript 写的 QQ AI 猫娘，通过 OneBot v11 接入 QQ，使用支持工具调用的 OpenAI 兼容接口。

支持多个白名单群，每群独立 Listener 实例和记忆。支持 @／引用接话、随机插话、群内共享记忆、分条发送与真实 @，也能查询成员。禁言、解禁、撤回成员消息、改群名片可分别配置为关闭、需要主人确认或自主直接执行，默认关闭；不提供踢人、公告或修改群设置。

## 配置和运行

建议 Node.js 24+，并准备可用的 OneBot v11 WebSocket 服务。

```sh
npm ci
npm run faces:sync  # 获取完整 QQ 原生表情目录（需要联网）
# 仅首次配置；不要覆盖已有文件
cp config.example.toml config.toml
cp .env.example .env
# 编辑配置、填写密钥，再把 config.toml 的 [ai] enabled 设为 true
npm run config:check
npm run build
npm start
```

- `config.toml`：模型、连接、触发概率、记忆与工具开关，不入库；注释见 `config.example.toml`。
- `.env`：仅放 OneBot Token 和模型 Key，不入库；也可用配置中指定名称的环境变量注入密钥，优先于文件。
- `prompts/listener.md`：人设与语气，入库。权限规则不放在人设里。
- 相对人设和记忆路径按 `config.toml` 所在目录解析。未知配置项或非法值会阻止启动，检查命令不联网、不创建记忆库。

旧版 `.env` 可用 `npm run config:migrate` 一次性迁移：保留实际参数，旧文件备份在 `data/config-migration.env.bak`；若已有 `config.toml` 则拒绝覆盖。迁移工具将旧版单群设置写成明确的 `groups` 白名单，不生成 `bot.group_id`；运行时不再从环境变量读取行为参数。

修改配置或人设后重启 Bot，暂不热加载。开发用 `npm run dev`，测试用 `npm test`；不要同时启动多个实例。需要做一次受控的真实模型观察验证时，明确执行 `npx tsx scripts/probe-observation.ts --allow-model-network`；该脚本使用合成事件、限制请求数，不连接OneBot、不发送QQ消息。

## 多群支持

一个进程共享 OneBot 连接、人设和表情目录；每个启用的群都有独立 Listener、模型实例与状态，不共享模型续接链。每个启用群按解析后的 `memoryPath` 创建 `${memoryPath}.events.sqlite`（追加式世界事实）和 `${memoryPath}.session.sqlite`（追加式模型会话与工具账本）；模型请求指标另存于全局 `${ai.memoryPath}.telemetry.sqlite`。这些是运行时路径派生规则，配置入口仍为全局／分群 `[memory].path`，不是新增的TOML路径字段。原有 memory SQLite 仍保留用于 legacy 历史和启动迁移，不把摘要当作原始事件。图片与转发读取必须核验本群来源，工具缓存不跨实例共享；私聊和未启用群的消息不进入群记忆，不处理命令。请勿为每个群再启动一个 Bot 进程。

```toml
[ai]
# 在现有 [ai] 表内添加，不要重复声明同一张表
max_concurrent_turns = 2

[groups."100000002"]
enabled = true

[groups."123456789"]  # 替换为实际群号；QQ 账号须已经在群里
enabled = true

[groups."123456789".reply]
random_probability = 0  # 这个群只响应明确呼唤

[groups."123456789".images]
enabled = false

# 可选：补充而不是替换全局人设，权限规则仍由程序强制执行
# [groups."123456789".persona]
# append_file = "prompts/group-tech.md"
```

全局设置作为默认值，群表可按字段覆盖 `ai` 中的transport、会话资源和压缩设置、唤醒工具预算和总超时、`reply`（含 `random`）、`tools`（含 `moderation`）、`images`、`forward`、`memory`、`attention`，或用 `persona.append_file` 追加本群风格。连接、模型、身份、主人及日志仍是全局配置，群内没有动态修改配置的命令。最多配置32个群，配置／人设变更后执行 `npm run config:check` 并重启。

**`groups` 是唯一的群白名单来源，其中所有 `enabled=true` 的群就是完整白名单**，不会额外启用任何群；未配置 `groups`、空表或全部关闭都意味着不服务任何群。`[bot] group_id` 已移除，配置中保留该字段会报错，请改用明确的群表。现有100000002群继续使用全局 `memory.path`，无需搬迁、清空或重新归属旧记忆；其他群默认使用该路径所在目录下的 `groups/<群号>/listener.sqlite`。可通过每群 `memory.path` 指定独立文件，启动前拒绝路径／符号链接／硬链接冲突；数据库内部绑定群号，错群打开会拒绝，不能靠修改配置把A群库改作B群库。

全局 `ai.max_concurrent_turns` 为1～8，默认2。名额覆盖整个唤醒（模型、工具和发送），从而限制模型并发；不是按人排队。每群最多占用／等待一个名额，按先到先得让等待群前进。等待名额时仍继续合批；开始后只固定触发调度元数据，不冻结后续工具可读取的世界事实。新群不会抢断正在处理的唤醒。单群重置只取消本群的当前／等待批次，断线和进程停止会取消所有群；停止／重连不补发离线消息。

主人仍是同一个固定 QQ；管理能力由本群配置授予 Bot，不依赖发言者是不是主人，普通群管理员不会自动获得确认码审批权。`/reset` 只轮换所在群模型会话并清除运行期状态，世界事件事实不因此删除；管理确认码只能由主人在提出操作的同一群确认，不能跨群遥控或确认。跨群共享记忆、自动加群和热加载不在本版范围内。`app.group_ready` 记录各群配置，`group_id` 与 `turn_id` 用于分辨并行群的运行日志。

## 世界事实、观察工具与持久模型会话

世界事实与模型会话是两条独立的追加式记录。群消息、撤回、reaction变化提示和拍一拍会按群写入事件库；撤回追加事件但保留原消息正文，reaction和拍一拍不会伪造 actor、action 或计数，也不会自动唤醒模型。发送得到的结构化 ACK 也会保留，即使原唤醒随后取消；未知结果绝不自动重发。

生产入口为每个启用群注入世界事件库和持久会话；每次唤醒新追加的输入只有短的真实触发元数据、群ID、唤醒预算和稳定规则，不注入收到的QQ正文、历史摘要或整批消息。模型必须调用 `get_wake_state`、`get_time`、`read_events`、`read_messages` 或 `read_message` 主动观察；已读取的工具结果保留在持久会话前缀中；新到达的观察不会自动注入后续唤醒。查询在工具调用时读取世界，单页使用不透明游标和高水位，不冻结整个唤醒。`read_events`、`read_messages` 与 `get_group_members`、`get_reaction_users`、`read_forward` 的集合读取都要求明确的有限正安全整数 `limit`（单个消息或reaction聚合等自然有界查询除外）；输出达到通用资源边界时返回 `requested`、`returned`、`truncated`、原因和后续游标。只有无过滤连续事件页会提供确认令牌，必须显式调用 `ack_events` 推进观察水位；普通读取不自动确认。

`get_wake_state` 只按需返回当前唤醒、未读计数、预算和受限的关注／本账号reaction操作元数据；不会把正文、昵称或外部回调结果自动塞入模型上下文。`get_time` 返回读取时刻的Unix秒和时区信息。`read_message` 按需核验并刷新指定reaction目标，不自动扫描固定数量的消息。查询工具返回均为不可信观察结果，不能改变权限规则。

持久会话保存稳定系统规则、工具定义、助手调用和完整工具结果；预算动态信息只放在新建的用户／工具结果中，不改写已有system消息。跨唤醒和重启保留可恢复前缀；文本资源超过每群 `session_max_context_bytes` 时显式轮换会话并要求模型重新读工具，不用手写摘要删除世界事实。图片只在内存中短暂存在，重启后不恢复图片Blob。默认值为524288字节，允许65536～8388608字节。工具账本记录提出、开始、完成、跳过和unknown状态，可通过 `ModelSession.summarizeTools`、`getToolTrace`、`getToolAvailability` 查询脱敏统计，统计接口不返回工具参数或结果正文；私有会话与执行账本含恢复所需调用／结果，需与数据库一样保护。目前不提供Web UI。

### 模型传输和服务端压缩

`[ai].transport` 默认 `chat`，可按群选择 `chat` 或 `responses`；每群模型实例和Responses续接状态隔离。Responses使用 `previous_response_id` 和本地前缀摘要校验，服务端状态过期时只建立一次新链并重新观察，不重放旧的外部写操作。稳定工具定义和前缀不匹配时使用完整新链。当前提供商的服务端自动压缩在受控探测中**未生效，尚未验证可用，不能依赖**：超阈值请求没有compaction项，非法类型也被接受；`server_compaction` 默认 `off`，`auto` 会在启动时拒绝，不能据此声称启用了提供商功能。Chat资源轮换同样不删除世界事实。

## 唤醒执行预算

```toml
[ai]
max_tool_calls_per_wake = 96
wake_timeout_ms = 90000

# 可选：按群覆盖，未写的字段继承全局
# [groups."123456789".ai]
# max_tool_calls_per_wake = 128
```

每次唤醒所有模型工具调用共享一个额度，默认96次（允许1～4096），总超时默认90000毫秒（允许1000～600000）。参数错误、未知工具、关闭的工具、核验拒绝、重复缓存命中都计一次；工具内部的QQ核验／reaction目标刷新请求和主人后续 `/confirm` 不计为模型工具调用。多调用响应按顺序处理，只执行剩余额度能容纳的前缀；预算耗尽不再调用模型或执行后续动作。预算信息只附加到新建的工具结果或触发元数据中，不每轮改写已有system前缀；日志记录实际工具调用数、模型请求轮数及终止原因。

不再另设模型4／8／10轮上限，也不再限制普通查询4次、管理1次、发送参数修正2次、转发读取6次、reaction32次、回应者查询8页或关注操作32次。模型无工具调用的普通正文不发送，直接结束，不空转。单次模型请求超时和token上限、图片容量、转发输出字符与嵌套深度、缓存资源大小、并存关注计划数量、真实权限与重复副作用防护仍保留。预算耗尽、总超时或取消不会回滚已经发生的QQ操作；没有正常结束的回合不提交暂存关注计划。

## 单条发送与明确结束

`send_message` 每次只发送一条消息，格式为：

```json
{"segments":[{"type":"text","text":"收到，我再核实一下。"}],"reply_to":"12345"}
```

`reply_to` 可省略。每条最多12个片段、合计800个文字字符和3个真正的 @，实际成员及引用目标仍会核验。发送成功返回 `message_id`，不会结束唤醒；可以继续读取、管理、添加 reaction 或再次发送。刚确认发送的自身消息会加入本轮范围，可随后引用、查询反应或撤回；生成期间新到达的群友消息可在后续工具查询中被观察，不会自动插入已有请求；任何读取或操作仍受相同群隔离和核验约束。

完成所有操作后调用 `finish({})`，不发消息时也直接用它结束。它与其他工具一样消耗一次额度；`finish` 后的工具一律不执行，也不再请求模型。多条消息应分多次调用，按顺序发送并保持节流，没有另设发言条数限制。发送失败或结果未知必须先看返回结果，不能把未确认送达当成功。

旧 `parts` 数组、顶层 `text` 简写、`reply.max_parts` 配置和 `stay_silent` 工具均已移除，不提供兼容别名；旧配置会直接报未知字段。

## 主动关注计划

```toml
[attention]
enabled = true    # 默认关闭；各群可在自己的 attention 表覆盖
max_plans = 16    # 每群并存计划上限，1～32，非发言条数限制
```

模型通过 `manage_attention` 安排何时再看本群：`create` 新增独立计划，`update` 指定 `plan_id` 替换该份，`cancel` 只取消指定计划。一次合批回复多个人可以建立多份等待，绝不以最后一份覆盖整个群。每份计划的 `any_of` 条件是“或”；命中后仅消费该份，其他计划保持原来的截止时间。多个计划同时命中合入同一待处理批次，不逐计划调用模型。

例如下面是一次工具调用参数（QQ号换成真实目标）：

```json
{
  "operation": "create",
  "purpose": "等对方补充版本信息",
  "any_of": [
    {"type": "member_message", "user_ids": ["123456789"]},
    {"type": "after", "delay_seconds": [300, 600]}
  ],
  "expires_in_seconds": 900
}
```

支持条件：`next_message` 等下一条；`member_message` 等指定成员任意一人；`after` 到随机选定的时间回来；`activity` 在 `window_seconds` 内满足 `min_messages` 条且 `min_senders` 个不同成员（缺省1人）。每份最多8个条件，成员条件最多16个QQ号；活跃度最多观察最近512条合格消息。时间以秒设置，有效期最长24小时，必须严格长于定时条件的最大等待时间。时间区间在提交时只抽一次，不随新消息不断推迟。

**随机抽签继续保留**，不需要主动关注也能照常运行；觉得不合适可自行把 `reply.random_probability` 设为0。@／引用、抽签、关注计划统一合批；@／引用不清空其他计划，也不会抢断正在处理的回复。纯关注唤醒也可使用本群已配置的管理能力，但计划文字不能修改能力模式或授权读取其他群。条件只决定何时检查，不代表必须说话，回来后仍可直接调用 `finish` 保持沉默。

计划操作先在本轮暂存：可以先设置再发言，也可以先发送消息再设置，最后必须调用 `finish` 正常结束才提交所有有效操作。发送消息、发送管理确认通知或仅设置计划都不会终止任务；`finish` 是严格的结束边界，之后不执行任何工具。失败、取消、超时、预算耗尽或仅输出普通正文不提交暂存计划。被其他事件消费、到期或更新的旧计划不会被本轮过时操作复活，提交结果通过后续 `get_wake_state` 按需查询，不自动注入模型上下文。

新建／更新计划在本轮结束时生效，消息条件只匹配提交后到达的消息；不把分条回复期间已经到达的消息算成未来的“下一条”。定时检查可以读取此前尚未处理的新消息；没有未读消息时不调用模型、不凭空开话题，到点的定时条件会等待新消息直到计划失效。机器人自己发的消息、命令、私聊和其他群不会触发。关注引擎的运行期未读缓存每群最多128条，超限有省略提示；这与世界事件库中由 `ack_events` 显式推进的观察水位不同。当前计划、剩余时间和命中原因通过 `get_wake_state` 返回的 `attention_state` 按需提供，过长的条件详情明确标注省略，不记录到日志。

计划、未读进度和活动计数均为每群独立的运行期状态；`/reset`、断线、停止或重启清空，不恢复过时期待；模型只有在调用 `get_wake_state` 时才能看到仍存在的计划元数据。未设置计划或计划已到期时，仍靠原有 @／引用和随机入口开启下一轮，不额外启动默认巡查。`attention.wake`／`attention.commit` 日志只记录群、批次、数量和状态，不记录计划内容。

## 回复批次

不逐人排队，也不让后来的人覆盖先前请求：

- 空闲时第一次 @／有效引用开启 `[reply] delay_ms` 收集窗口，合并补充消息及其他人的呼唤用于调度；消息内容写入世界事件库，由模型主动读取，后来消息不会不断延长窗口。
- 当前唤醒开始后，触发元数据和权限范围固定，工具读取按调用时刻观察世界；期间的新消息不会自动插入已有模型请求，但可由本轮或下一批显式读取。
- 当前批次结束，有新呼唤或关注计划命中就合批处理；否则只有普通消息时对这一批进行**一次**随机参与判断，沿用概率、冷却和每分钟次数限制。随机入口没选中就消费该批次，不逐条重抽或之后补抽；启用关注计划时，尚未读过的消息仍可由之后的计划检查。
- 等待窗口已经过去就不重新等整段时间，仍遵守群回复冷却。重置、断线、停止和处理超时仍会取消；需要远程核验的引用未完成时不会混入已开始的批次，核验成功后再加入待处理批次。
- 调度批次最多保留64条消息，优先保留最早的明确呼唤，普通消息保留较新的；这是唤醒调度边界，不是世界事件查询范围。模型观察工具另有明确的分页和输出资源边界，不自动注入批次正文。模型仍可合并回复或保持沉默，不保证逐人逐条回答。
- 普通群员、主人、混合呼唤、随机参与或关注唤醒均使用本群同一份管理能力配置，不要求主人先明确提出请求。来源身份和省略标记仍保留，不能把未核验转发声称的身份当成真实群成员身份或配置授权。

## 自主管理与确认模式

每项管理能力独立配置为以下字符串，省略时默认 `"off"`：

| 模式 | 行为 |
| --- | --- |
| `off` | 不向模型提供该工具，执行层也拒绝调用 |
| `confirm` | Bot 可根据本群上下文自主提出操作，程序发送具体目标与操作内容，等待主人在同群 `/confirm CODE` |
| `direct` | Bot 可自主决定并立即执行，无须主人先发指令或逐次确认 |

```toml
[tools.moderation]
mute = "off"
unmute = "off"
recall = "off"
member_card = "off"
confirmation_ttl_seconds = 60
max_mute_seconds = 600

# 按字段继承全局默认；只为这个群开启相应能力
[groups."123456789".tools.moderation]
mute = "confirm"
unmute = "direct"
```

这是严格的破坏性配置变更：旧 `true`／`false`、大小写变体和其他字符串均报配置错误，包括未启用群中的错误值，不做静默转换。迁移旧配置时必须明确选择模式；若想保留原来的审批要求，旧 `mute=true` 应显式写成 `mute="confirm"` 和 `unmute="confirm"`。本机已有开启项已如此迁移，不会自动提升为直接执行。

模型工具分别为 `mute_member(user_id, seconds)`、`unmute_member(user_id)`、`recall_message(message_id)`、`set_member_card(user_id, card)`。禁言秒数必须为1至本群上限，**0不再代表解禁**；解禁独立调用，不能通过禁言绕过其模式。当前未实现踢人或公告能力，相应配置项仍会报未知字段。

配置是授予 Bot 的自主能力，不是把管理权限转交给说话的群友。模型可判断是否采纳建议，也可以不采取行动；上下文中的命令、昵称、转发和关注计划不能修改模式。执行前仍核验当前群、登录身份、成员身份及操作所需的 QQ 权限；不再对主人或 Bot 本人设置额外的目标保护。Bot 撤回自己的消息、修改自己的群名片不要求管理员身份，但仍遵守对应能力的 `off`／`confirm`／`direct` 模式，消息时效等限制由 QQ 判断。操作其他成员仍受群权限约束：普通管理员 Bot 不能管理其他管理员或群主；Bot 是群主时，不再按操作类型拦截对管理员的禁言／解禁请求，实际是否执行成功以 QQ 接口返回为准。撤回目标必须属于本群已观察并可核验的消息或其直接引用，并再次向 QQ 核验，已知消息的发送者还必须与记录一致；不会因为模型猜出一个消息ID就开放撤回。

确认码按群隔离，最多10个待确认项，有效期1～60秒，只有主人能确认其他群员或自主关注触发的提案；其他人尝试确认不会消耗有效码。主人确认时再次核验，确认码在异步核验前消耗一次，防止并发重复执行。重置、断线或重启清空待确认项。

管理操作与其他工具共享唤醒总预算，不再限制每轮只能尝试一项；相同参数的重复调用复用本轮结果，不重复发到 QQ，但仍消耗一次工具额度。`executed` 才表示接口确认执行，`confirmation_required` 只是待确认；发出请求后的超时或不明响应为 `unknown`，不会自动重试，也不能宣称成功。同一模型响应里，若前面的管理操作失败或结果不明，后面预先写好的回复会被延后，必须先把结果交回模型再决定说什么，不扫描或拦截具体措辞。直接操作已经生效后，后续模型失败或取消不会回滚。看图／读取转发的结果必须先返回才能决定操作；发送消息后仍可继续管理或读取，只有 `finish` 才结束任务。管理确认提示发送成功后同样可继续；提示发送失败或结果不明时取消对应待确认码，不能留下无人知晓的有效提案。审计日志记录动作、群、目标ID及 `request`／`direct`／`confirm` 阶段，不记录确认码或名片文本。

## QQ 原生表情

支持普通和超级表情，与文字、@、引用混排，也可以只发表情。模型在 `send_message` 的 `segments` 中使用 `{"type":"face","id":"375"}`，程序转换成 OneBot `face` 消息段；只开放 ID，不开放 `chainCount`／`resultId`。不另设每条或每轮的表情数量配额，沿用每条最多12个片段、统一唤醒调用预算及发送节流；关闭 @ 功能不影响表情。

超级表情若要展示大表情效果，建议单独调用一次 `send_message`、只放一个 `face`，且不设置 `reply_to`；文字、@ 和引用通过另一次调用发送。混排和带引用仍允许用于有意的小尺寸展示，程序不擅自拆分，不增加表情数量配额。

模型通过 `read_messages`、`read_message` 和 `read_forward` 看到的内容保留有序 `segments`，不把原生表情、@、图片和转发拼成正文中的人工标记；默认唤醒不会自动提供接收消息或Bot历史。例如 `[{"type":"text","text":"围观一下"},{"type":"face","id":"271","name":"吃瓜"}]`；`face.name` 是目录提供的辅助说明，发送工具也接受它但不传给QQ，实际表情只由 `id` 决定。未知原生表情保留合法 ID、不猜名称。发送仍只接受已加载目录中的 ID，防止 NapCat 静默丢弃未知表情；Unicode emoji 仍是普通文字，商城表情包和收藏图片不属于此功能。

文字就是文字：`text` 内的 `[QQ表情：…]`、`[at:…]` 或 CQ 样式字符串可以原样引用和讨论，程序既不拒绝这些字样，也不把它们自动升级成真实操作。出站始终使用 OneBot 消息片段数组；[已核对 NapCat 4.18.28 的发送归一化](https://github.com/NapNeko/NapCatQQ/blob/v4.18.28/packages/napcat-onebot/action/msg/SendMsg.ts)，CQ 解码只作用于顶层字符串消息，数组中的 `text` 不会被解码成操作。真正的提及必须用 `at` 片段，并继续核验本群成员、功能开关、数量及禁止全体／自己的限制。收到的 `at.user_id`、`reply.message_id`、`image.image_id` 和 `forward.forward_id` 各自保留类型；媒体引用的 `not_viewed`／`not_read` 不是已读取内容，也不会携带原始URL或转发资源凭证。普通文字中的媒体样式标记不授予新记录的媒体读取能力。

legacy memory SQLite 的新记录仍保存经过净化的结构化内容，不改数据库表结构；启动迁移只把真实消息转成事件，绝不把旧摘要伪造成原始事件。内部兼容用的旧 `text` 字段不会与新 `segments` 重复交给模型；旧记录无法可靠区分原文和旧标记时，用 `representation=legacy_text` 明示保留，不做正则迁移或自动猜测。模型会话不自动读取这些记录，内容需要通过观察工具按需读取；内容按序裁剪并用 `content_truncated`／`segments_omitted` 等独立字段说明，不插入冒充原文的截断标记。

`npm run faces:sync` 从固定的 NapCat **4.18.28** 来源同步完整目录到 `data/qq-faces.json`，重启后加载，平时收发不联网查目录。未同步时仅有少量独立编写的示例映射；已存在但损坏的目录会明确报错，可重新同步修复。完整上游原文件与许可证保留在被 Git 忽略的 `data/` 下，不随源码分发；上游采用限制性再分发许可，公开打包数据前需另行核对许可。普通和带动画配置的 ID 都可选择，具体动画呈现仍取决于 QQ 客户端。

## 消息表情回应（reaction）

```toml
# 添加到已有 [tools] 表中，不要重复声明同名表
[tools]
reactions = true   # 默认 false；各群可在自己的 tools 表独立覆盖
```

开启后提供 `react_message`，与发送一条 `face` 消息不同，它在目标消息下面添加／取消 Bot 自己账号的表情回应，不额外发送聊天气泡。参数为 `message_id`、`emoji_id`（均为字符串）和 `action`（`add`／`remove`）；底层通过现有 OneBot 连接调用 `set_msg_emoji_like`，转换为 `set: true`／`false`。不需要主人确认，独立于成员查询、@、管理工具开关；关闭功能不删除已经添加的回应。

候选目录直接复用 `faces:sync` 留下的完整 NapCat **4.18.28** 原始资源：`sysface` 的329条使用 `QSid`，`emoji` 的165条使用 `QCid`，合计494条，不人为缩成少数常用表情。工具同时展示名称、类别及 Unicode 字符；不能把 `EMCode`、emoji字符本身或 QQ 内部消息长ID当成参数。目录是候选集合，不保证QQ接受所有项；业务拒绝会反馈给模型，不把外层请求成功当作反应成功。完整上游资源及许可证仍只放在忽略的 `data/`，不嵌入源码。原始资源缺失时仅使用8个独立编写的示例，执行 `npm run faces:sync` 后重启可恢复完整目录；已存在但损坏的资源不静默降级。未启用 reaction 时不加载它的目录。

目标必须是本群已记录的可核验消息，或是本群消息的可核验引用；每次真正变更前都用 `get_msg` 再次核对所属群、消息ID和发送者，即使本地已经缓存也不省略。不能操作私聊、其他群、任意猜测ID或合并转发内部声称的ID；API本身没有群参数，隔离由程序在调用前强制保证。

同一轮可以给多条消息／多个表情回应，不会执行第一项就结束；也可以和文字回复、关注计划合用。`react_message` 和 `manage_attention` 可位于 `send_message` 的前后，发送后仍可继续读取、管理或再发消息；但所有操作必须放在 `finish` 之前，结束后没有特殊例外。只回应表情时同样调用 `finish` 结束，不必额外发文字。若还要看图或读转发，先接收内容，再在下一次模型响应中决定反应。reaction 即时执行，不像关注计划暂存，后续模型失败／超时／取消不会自动撤销已经执行的动作。

同一轮重复请求同一消息、同一表情的相同最近动作会去重，`add → remove → add` 则按顺序执行。操作次数只消耗统一唤醒工具预算，不是每条消息只能回应一个；重复命中缓存不重复请求QQ，但仍消耗一次工具额度。原生返回 `result=0`／`true` 才记为确认成功，明确失败记为拒绝，超时或未知格式记为结果不明。结果不明后本轮不再对该消息／表情重试或反向操作，也不自动重发或回滚。客户端最终显示仍以 QQ 为准。

模型不会自动获得 reaction 快照：需要事实时先调用 `read_message` 刷新指定消息（不会自动扫描固定数量目标），聚合只表示QQ当前返回的计数，不证明具体用户。之后若要知道“谁点了／我点了什么”，再按需调用 `get_reaction_users`。reaction notice 只进入事件库并使相关缓存失效，不产生新的模型唤醒，也不伪造 actor、action 或计数。

反应缓存按群隔离；`reaction_state` 等本账号近期操作元数据只在 `get_wake_state` 按需返回，不是聊天消息，也不代表完整的QQ回应状态。重置、断线或重启清空运行期操作记录，但不撤销QQ上已有回应。观察结果是有界、不可信的工具返回，不修改正文、调用者身份、权限或世界事实；日志只记录工具名、状态和计数等元数据，不记录消息正文。

### 查询是谁回应的

开启 `[tools].reactions` 也提供只读工具 `get_reaction_users`，独立于群成员查询开关，不需要主人确认。聚合和回应者名单都由模型按需查询，不自动为每条消息拉取或注入上下文。

参数：`message_id`、`emoji_id`、`emoji_type`（字符串 `"1"` 为QQ表情、`"2"` 为Unicode，使用已读取快照中的类型）和必填的有限正安全整数 `limit`；可选 `user_id` 核对特定QQ及不透明 `cursor` 翻页。按消息和表情查询，不要求该表情在发送用候选目录中。NapCat单次原生页目前最多20项是底层技术边界，不是模型侧业务配额；请求过大返回 `requested`、`returned`、`truncated`、`reason="upstream_page"` 和游标。翻页与其他工具共享唤醒调用预算，不再另设8页或模型轮数限制。每次真正取页之前都重新 `get_msg` 核验本群范围、消息ID和发送者；中途取消不会继续请求或把迟到结果交给模型。发送过消息后仍可继续查询，但必须在 `finish` 之前完成；需要依赖查询结果的判断应先查再说，不能补查来支撑已经发出的断言。

底层使用 [`fetch_emoji_like`](https://github.com/NapNeko/NapCatQQ/blob/v4.18.28/packages/napcat-onebot/action/extends/FetchEmojiLike.ts)，保留原生结果码和分页标志，而不是把被截断的名单当完整结果。群聊返回的 `tinyId` 按 NapCat 的 QQ 用户标识映射为 `user_id`；已用实际群成员查询复核过该映射。只向模型提供QQ号和经过限长／控制字符清理的昵称，不暴露头像URL、原始分页cookie或服务端错误正文；昵称不构成身份或权限凭据。

返回 `users` 为本页新增回应者，`seen_users` 为本条查询链累计去重数，`complete` 表示是否无遗漏地遍历到明确末页。`has_more`／`next_cursor` 指示是否继续；模型游标是本轮独有的不透明标识，绑定消息、表情、类型和可选目标QQ，不能跨查询或跨轮复用。原生协议有时需要在最后一个非空页后再读一个空末页，程序不会提前认定完成。

传了 `user_id` 时，`target_found=true` 表示已经在本条查询链任意一页找到目标，可直接停止分页；`false` 只在完整、无缺失的查询中未找到时返回，其他情况为 `null`。坏行、重复／停滞分页、缺失标志、预算耗尽等不会被解释为“这个人没点”。这只是本次读取的当前名单，不证明历史上从未点过，也不提供每人次数或点击时间，翻页期间名单可能变化。

重复请求复用本轮缓存。若本轮随后对同一消息／表情执行添加或取消（包括结果不明），对应名单缓存和旧游标失效，重新查询会从首页读取；不会清零页面预算，也不影响其他消息的游标。工具名单不会伪造成新的聊天事件；已向模型返回的工具结果会保存在私有模型会话中，程序不根据回应者身份提升管理权限。

## 图片

使用同一个 `[ai]` 模型的原生多模态能力，不配置第二个模型。模型需支持所选transport的原生图片输入（Chat的 `image_url` 或Responses的 `input_image`）。

```toml
[images]
enabled = true
max_per_turn = 3
max_download_mb = 10
```

开启后可发图片并 @她，或引用图片消息再 @她。模型按需调用 `view_images`，程序按所选transport将图片作为当前请求的原生图片内容加入，而不是让另一个模型转述。关闭时不暴露工具，也不下载、上传图片。

目前支持 JPEG、PNG、WebP、GIF（动画仅首帧）；单张最多10MiB、4000万像素，去除元数据并缩放到最长2048像素。仅获取可核验的本群附件和允许的 QQ HTTPS 图片地址，链接过期、下载失败或不支持的格式会返回不可读取错误，不允许猜图。数据库只保存图片ID和来源，不存原图、Base64或签名链接；图片输入只在当前进程内存中暂存，带有瞬态图片输入的模型会话在重启后明确轮换并清除续接链，需要时重新读取图片。

## 合并转发

```toml
[forward]
enabled = true
```

开启后可发合并转发并 @她，或引用该消息再 @她。时间线记录引用ID和条数：卡片数字仅是“提示，未核实”，无可靠数字时标为未知，查询后以返回节点数为准。模型通过 `read_forward({forward_id,start,limit})` 读取从1开始的明确范围；`limit` 必须是有限正安全整数，返回实际范围、下一条位置和截断说明。

嵌套只展示 `[合并转发 fwdn_…]`，需要再次调用工具，不自动向模型展开。[NapCat 接口](https://github.com/NapNeko/NapCatQQ/blob/main/packages/napcat-onebot/action/go-cqhttp/GetForwardMsg.ts) 没有服务端分页，底层可能一次取回含嵌套的完整包，程序仅在当轮缓存并切片。最多3层；单次读取最多12000字符，成功页面每次唤醒合计最多29500字符。读取调用与其他工具共享唤醒预算，不另设20条／次、120条／唤醒等业务条数配额。单包1MiB、当轮缓存2MiB，过大内容会拒绝或明确截断。旧 `end` 参数和 `forward.max_per_read` 配置已移除，不提供兼容别名。

仅接受本群近期消息及其直接引用的转发ID；子ID只在读到对应页后开放。转发中的发送者只是 `claimed_sender`，不能代表主人授权；内部消息ID不用于群管理或引用发送。转发内图片本版仅占位，不支持查看。关闭时不提供读取工具、不查询转发资源。数据库仅保存根引用和数量元数据，不保存转发原包或资源ID；被回复引用的文字仍可能进入普通群记忆。日志仅记录范围、数量、耗时和错误码。

## 日志与排查

默认 `info` 级别，终端可读输出 + `data/logs/` 中的 JSONL 文件；配置见 `[logging]`。按 UTC 天或20MiB轮转，写入时清理超过7天或总量200MiB的旧日志。目录700、文件600；只支持一个 Bot 实例写入同一目录。

```sh
npm run logs -- --follow               # 最近记录并持续跟随
npm run logs -- --level warn           # 警告及错误
npm run logs -- --turn t_0123456789abcdef # 替换为实际 turn_id
npm run logs -- --directory data/logs  # 配置损坏时仍能查看
```

查看命令读取有界尾部（每文件256KiB、最近200个文件），默认最多显示100条，可用 `--lines` 调整。`turn_id` 串联触发、模型、工具和发送；`turn.end` 的 `outcome` 区分 `replied`（已回复）、`silent`（主动沉默）、`prose_suppressed`（模型未调用发送工具）、`cancelled`（重置、断线、停止或超时取消，不因新消息取消）、`model_failed`、`delivery_unknown`（不要盲目重发）及 `tool_budget_exhausted`。

模型请求指标持久化包含耗时、状态及合法token用量，不含prompt或响应正文。`inputTokens` 是含缓存的总输入；`cachedInputTokens` 是输入子集，`reasoningTokens` 是输出子集，计算总量不能再次相加。缺失字段保留未知；缓存率仅对输入与缓存字段都已知的请求加权计算，并报告覆盖率和缺失数。工具统计与暴露集合可通过 `ModelSession.summarizeTools`、`getToolTrace`、`getToolAvailability` 查询，统计／trace输出不包含工具参数或结果正文；执行账本和模型会话本身仍是私有会话数据。目前没有Web统计面板。模型日志包含耗时、HTTP错误分类和服务商返回的合法 token 用量；图片日志区分来源核验、DNS、下载、解码。`debug` 额外显示普通消息被跳过的原因，修改级别后需重启。**所有级别都不记录聊天正文、人设、模型内容、图片、密钥、签名链接、管理确认码或群名片内容**，但含 QQ／消息ID，请勿随意公开。写入故障或队列满会丢弃日志并限频警告，不影响 Bot；控制台阻塞不会拖住文件日志。
