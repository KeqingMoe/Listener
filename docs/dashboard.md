# Bot 运行诊断面板

用于查看唤醒、模型请求、工具执行和接入事件。业务接口只读本地数据，不连接 OneBot、不调用模型、不重放工具。登录和退出仅改动面板自身的会话状态。

## 启动和登录

```sh
npm run dashboard:build
npm run dashboard:start
# http://127.0.0.1:3210/
```

服务使用仓库的 `config.toml`／`.env`。默认监听 `127.0.0.1:3210`；通过 `--host`、`--port` 或进程环境变量 `DASHBOARD_HOST`、`DASHBOARD_PORT` 指定监听位置。裸 `--host` 表示所有 IPv4 接口，非必要不要使用。

在同目录私有 `.env` 中配置 `DASHBOARD_PASSWORD`：至少12字符、最多256字节，不含换行等控制字符。不要复用OneBot或模型密钥。进程环境中的同名值优先，包括显式空值；配置只在启动时读取，修改后重启面板服务。

没有配置或配置无效时，页面拒绝访问，业务API也关闭。修改密码需编辑 `.env` 并重启；删除或更换密码会撤销已有会话，恢复旧值也不会恢复旧会话。

用浏览器普通密码表单登录。密码不放URL，也不输出到日志；Cookie为HttpOnly、SameSite=Strict，会话最多保留7天，相同密码下重启仍有效；退出撤销当前会话。`storage.directory/dashboard-auth/auth.sqlite` 仅保存环境凭证变化检测用的单向哈希及会话摘要，权限0600；它不是独立密码来源。

面板包含群消息、模型上下文及工具内容，必须限制到授权人员。远程使用受控的Tailscale ACL／SSH转发，或正确配置的HTTPS入口；不要将HTTP密码登录直接暴露在公共网络。HTTPS部署可显式设置 `DASHBOARD_COOKIE_SECURE=1`；服务不会因为客户端伪造的转发头就信任HTTPS。生产服务缺少鉴权存储时拒绝启动，没有匿名诊断模式。

## 视图和审阅

- **总览**：请求结果、token三分、缓存命中率、TTFT／TPS、模型／工具累计时间、延迟及本地接收状态。总量Token条只在总览出现，不占用其它页面顶部空间。
- **唤醒**：筛选和分页；侧栏按过程、对话、请求和事件审阅。
- **模型请求**：包含已开始但尚未结束、成功、失败、超时、取消和中断的请求。展开查看实际请求／响应快照、可用推理、错误和工具调用。
- **工具**：按执行结果与耗时统计；在请求或唤醒详情中查看具体参数和返回值。
- **事件**：查接收、触发／跳过、连接、发送和运行事件，包括没有生成唤醒的情况。

表格与详情独立滚动；桌面可拖动分栏或用分隔条左右方向键调宽，窄屏使用独立详情。Esc关闭详情，前后条浏览列表记录。响应链的前序／后续链接与列表前后条分别导航。筛选及选中记录保留在URL，内容支持搜索、JSON树／原文和复制。复制总是使用完整原文，不受搜索过滤影响；HTTP环境不依赖安全上下文Clipboard API，失败时提供可选中的全文供手动复制，不会虚报成功。

正文是数据，不执行HTML，不自动加载其中的远程图片。普通消息、业务参数及消息／响应ID可查看；API密钥、Authorization、Cookie、密码、确认授权码等真正凭证仍被保护。大图片base64和不可读的加密推理只保留省略标记。显示的思考仅来自服务商实际返回的文本或摘要，无法从加密内容或token计数还原。

## 计量口径

- **输入／缓存／输出**：输入是未缓存输入，即服务商总输入减缓存输入；缓存是命中的输入；输出沿用服务商计量。推理token若包含在输出中，不重复相加。
- 缓存缺失不等于零。无法拆分的输入不会冒充未缓存输入；缺失值用短横，聚合仅计算已知样本。
- **缓存命中率** 在总览、唤醒、请求采用同一公式：仅使用总输入与缓存计数有效配对的样本，缓存量之和／同一批样本的总输入之和。不平均各请求百分比；未知不当零，总输入为零时比率未知。
- **TTFT** 为请求发出至首个有效输出前的等待时间；汇总显示具有计时记录请求的平均值。空事件、心跳或仅包含角色的事件不算有效输出。历史缺少流式计时的请求显示 `—`，不按HTTP总耗时倒推。
- **TPS** 为输出token合计／同批成功请求从首个有效输出到协议完成的耗时合计；协议完成指Chat的`[DONE]`或Responses的`response.completed`，包含输出后的usage与结束事件等待，但不含TTFT。不平均单条TPS，也不使用筛选窗口长度作分母。只要有有效首输出、协议完成、输出用量且完成时间晚于首输出就计算；单个或同一批到达的delta也不自动丢弃，reasoning和工具调用delta同样可触发计时。历史旧口径不混入新统计。总览散点支持独立选择TTFT（秒）和TPS（tokens/秒），保持原始请求时间与缺失值。
- TPS分子沿用服务商完整`output_tokens`，不减首token，不重复加`reasoning_tokens`。沿用`ttft_ms`和`decode_duration_ms`，不增加计时列；观测区间为零时保存`0`，但TPS显示`—`且该样本不参与TPS聚合。以前被过滤成`NULL`的计时不补算。此指标是客户端观测吞吐率，网络缓冲、短输出及不可见推理可能造成偏差，不是服务端硬件解码速度。
- **模型累计** 汇总已结束且耗时已知的HTTP请求，包含失败；不是TPS分母。**工具累计** 汇总账本中实际开始到结束的时长；包含本地工具及外部交互，不等同纯NapCat网络耗时。
- 唤醒的**模型墙钟**使用请求时间区间的并集，避免并发／嵌套重复计算。**非模型耗时**为唤醒墙钟减模型区间并集，可能包括工具、自动上下文准备、数据库访问和调度等，不能称为纯数据库或NapCat响应时间。工具累计与墙钟可能重叠，不能直接相加；单HTTP请求不推测后续工具耗时。
- 跨会话轮换关联到同一执行轮的请求保留可读性，但超出当前唤醒边界时不伪造墙钟拆分；总览直接按请求ID去重，不把可能重叠的唤醒关联视图累加。缺少计时或数据源时显示未知，已知部分附覆盖信息。进程重启时发现的中断请求，恢复检查时刻不是HTTP真实结束时间；没有真实结束记录就不将停机时间算进模型耗时。
- 请求与整轮唤醒是不同单位。请求成功不等于已经回复；工具完成不等于QQ最终效果；取得接口回执不保证收件人已经看到。
- 所有时间线关联使用已持久化的请求、会话、唤醒和工具关系，不按接近时间猜测。

## 数据来源与保留

运行指标在 `storage.telemetry_path`；私有请求快照和结构化运行事件也存放在该数据库的独立表。会话、工具账本和群事实使用当前群配置对应的只读数据库。显式启用的群可查看历史；动态发现的群仍受有效注册租约和当前启用策略约束。

请求在开始时记录，结束时补齐结果。没有请求快照时，面板可展示已有会话记录并标明来源；会话记录不等于完整HTTP快照，无法还原未保存的推理、错误正文或响应链。

私有快照的保留目标为7天、256MiB逻辑内容，单个请求／响应字段最多1MiB，其余诊断文本最多64KiB。清理由后续写入触发，按有界事务批次渐进执行；积压期间可能暂时超过目标，SQLite文件的已分配页会复用，不承诺物理文件立即缩至256MiB。运行事件保留目标为7天、约30000条。达到记录或展示上限时明确标记截断；不会为了展示而扩大原模型响应上限。

范围最多31天。列表有分页与扫描上限；正文只在详情加载，并限制单个审阅响应的总量。面板只读连接不会执行会话恢复或修改bot数据库。接入异常见 [运行排障](operations.md)。

## 构建与测试

```sh
npm run typecheck
npm run dashboard:test
npm run dashboard:test:browser
npm run dashboard:build
```

服务端入口为 `dist/dashboard/server/index.js`，页面产物位于 `dist/dashboard/web/`；Node模块与Bot共用 `dist/` 下的模块树。

## 文件权限

systemd服务需能读取bot数据，只允许写入自己的 `storage.directory/dashboard-auth/` 认证子目录（SQLite需要创建journal文件）；部署时预先创建该目录，权限0700、属主为服务用户。将 `ReadWritePaths` 限定到此子目录，而不是整个bot数据目录，保留群事实、会话和遥测的文件系统只读边界。不要给予任意QQ管理或日志执行接口。
