# 运行排障与恢复验收

面板使用与登录见 [Dashboard](../dashboard/README.md)。配置项仍以 [配置说明](configuration.md) 为准；本页只说明运行问题。

## 群内提及后没有唤醒

先在面板选择对应群和时间，在“事件”查看接收与触发记录：

1. **没有收包记录**：核对接入连接、进程心跳和最后真实入站消息时间，再检查QQ账号登录／限制状态。进程存活、`onebot.ready`、身份查询甚至部分“在线”接口，都不能证明QQ仍正常接收消息。群安静也不能直接判成离线。
2. **收到了但未触发**：查看触发跳过的具体原因和群配置。不要立即增加模型预算，问题还没有到模型阶段。
3. **已经触发但没回复**：打开对应唤醒，检查请求、工具和结束原因。发送已经取得回执后，后续请求仍可能超时或被取消；不能把整轮失败理解为从未发送。

账号需要重新登录或解除限制时，由账号持有人通过手机QQ和官方流程处理。二维码属于登录材料，只保存在受限权限且被Git忽略的运行目录，不提交仓库、不上传第三方二维码网站。不要用反复重启、重放历史提及或补发管理操作来代替排障。

## 模型慢、失败或取消

模型请求与整轮唤醒是不同计量单位：单请求受 `model.timeout_ms` 约束，整轮的请求、工具及续接恢复共同受 `execution.wake_timeout_ms` 约束。后续请求可能尚未到自身时限，就因整轮剩余预算耗尽而取消。

面板请求详情可比较：

- 请求总耗时、输入／缓存／输出和端到端TPS；非流式模式没有真实TTFT，不根据总耗时倒推。
- 实际请求与响应、服务商提供的推理文本／摘要、错误正文。
- 响应编号及前序响应链，区分新请求、续接和恢复续接。编号是定位线索，不是错误原因本身。
- 工具参数、返回值和操作回执；被拒绝、正常延后、跳过、未知结果分别对待。

请求失败、超时、取消和中断不能合并成一种失败。看图／读取转发后的顺序屏障以及等待管理复核属于正常延后；未知结果不等于确认失败。普通400不会因新增诊断而自动重试，诊断采集不会重放写操作。Chat错误正文只作短时限尽力采集，正文不完整会标记，不让已知HTTP失败因诊断等待改成模型超时。

## 修改或重启后的验收

- 只改面板时只重启面板，验证原地址、登录和内容读取，不另起服务冒充替换。
- 更新bot前检查当前是否有活动唤醒，优先等待其正常结束；先备份私有数据库，保留可回退构建。
- 健康检查至少区分进程／连接与真实业务链路。恢复接收的完整证据是：真实入站消息进入本地、生成新的唤醒、请求和工具产生实际结果，面板显示相同记录。
- 没有自然流量时，只能报告连接和页面验证通过、真实收包尚待流量验证。不要主动发送测试群消息或重放旧指令制造“通过”。

原始群事实、会话账本、请求快照和认证文件都是私有数据。排障统计可对外给出安全摘要，不把完整聊天、参数、返回值、登录密码或原始数据库混入公共测试与文档。
