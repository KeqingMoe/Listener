# 运行排障

面板使用与登录见 [Dashboard](dashboard.md)，配置项见 [配置说明](configuration.md)。

## 群内提及后没有唤醒

先在面板选择对应群和时间，在“事件”查看接收与触发记录：

1. **没有收包记录**：核对接入连接、进程心跳和最后真实入站消息时间，再检查QQ账号登录／限制状态。进程存活、`onebot.ready`、身份查询甚至部分“在线”接口，都不能证明QQ仍正常接收消息。群安静也不能直接判成离线。
2. **收到了但未触发**：查看触发跳过的具体原因和群配置。
3. **已经触发但没回复**：打开对应唤醒，检查请求、工具和结束原因。发送已经取得回执后，后续请求仍可能超时或被取消；不能把整轮失败理解为从未发送。

账号需要重新登录或解除限制时，由账号持有人通过手机QQ和官方流程处理。二维码属于登录材料，不提交仓库、不上传第三方二维码网站。不要用反复重启、重放历史提及或补发管理操作来代替排障。

## 模型慢、失败或取消

模型请求与整轮唤醒是不同计量单位：单请求受 `model.timeout_ms` 约束，整轮的请求、工具及续接恢复共同受 `execution.wake_timeout_ms` 约束。后续请求可能尚未到自身时限，就因整轮剩余预算耗尽而取消。

面板请求详情可比较：

- 请求总耗时、输入／缓存／输出、TTFT和TPS。TTFT为首个有效输出前的等待；TPS用首个有效输出至协议完成（Chat的`[DONE]`或Responses的`response.completed`）的耗时，包含usage／结束事件等待而不含TTFT。失败、缺少终端或历史没有新口径计时的记录显示未知；单个delta、批量delta、reasoning和工具调用不会仅因形态被排除，不按HTTP总耗时或末个文本delta倒推。
- 实际请求与响应、服务商提供的推理文本／摘要、错误正文。
- 响应编号及前序响应链，区分新请求、续接和恢复续接。编号是定位线索，不是错误原因本身。
- 工具参数、返回值和操作回执；被拒绝、正常延后、跳过、未知结果分别对待。

请求失败、超时、取消和中断是不同状态。看图／读取转发后的顺序屏障以及等待管理复核属于正常延后；未知结果不等于确认失败。普通400不会自动重试，诊断采集不会重放写操作。Chat错误正文只作有时限的尽力采集，正文不完整会标记。

群事实、会话账本、请求快照和认证文件均包含私有数据，不应作为公开排障附件。
